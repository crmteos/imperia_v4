# Специфікація Локального Інженерного Середовища та Архітектурного Стека проєкту Imperia v4 після Чистої Перевстановлення Windows 11

Розгортання суверенного локального обчислювального контуру проєкту Imperia (Ітерація 4) виконано в межах переходу на інженерну парадигму **Context Engineering v4.0**. Головною метою проведених робіт була повна ліквідація "антропоморфної помилки" та системного зашумлення контексту, що накопичилося в застарілих специфікаціях версії v3.0, а також забезпечення 100% автономності кодогенерації, математичних розрахунків та медіа-візуалізації без залежності від платних хмарних API.

## 1. Передісторія та Мета Розгортання Чистого Середовища

Попередні ітерації системи потерпали від критичного архітектурного розриву: описові веб-документи v3.0 створювалися для монолітних JS-інтерфейсів (`index.html`, `kassator.html`, `sl8_gateway.js`) і оперували виключно DOM-акордеонами та картками Leaflet. Водночас новий фізико-математичний апарат проєкту Imperia v4 (6D просторово-часова фізика Бартіні-Кузнецова, 204.08-октавна $M-f$ вісь, H3-сітки Uber та $Q$-фактор когерентності) вимагав потужного обчислювального ядра на Python із підтримкою GPU-прискорення.

Повна перевстановлення операційної системи Windows 11 та створення чистого інженерного середовища дозволили вирішити три фундаментальні задачі:

* **Контекстна чистота**: Вилучення із системної пам'яті застарілих та дубльованих файлів специфікацій v3.0, формування єдиного джерела правди в особі канонічного маніфесту `docs/imperia-v4-master-architecture-spec.md`.
* **Суверенітет обчислень (Zero-Budget Standard)**: Перенесення генерації коду, виконання тестів та рендерингу математичної графіки на локальне апаратне забезпечення ПК.
* **Чітке розділення предметного контуру та методології**: Фіксація проєкту "Imperia (Ітерація 4)" як метафізичної та фізико-математичної предметної області, а "Context Engineering v4.0" — як системного інженерного методу організації ШІ-пам'яті та розподіленого агентського середовища.

## 3. Локальний ШІ-Контур Безлімітних Обчислень (Ollama & qwen2.5-coder)

Серцем автономної кодогенерації є локально розгорнутий нейромережевий сервер **Ollama**, що працює за адресою `http://localhost:11434`. Сервер обслуговує спеціалізовану кодинг-модель **`qwen2.5-coder:latest`**, яка забезпечує високу точність синтезу Python-коду, математичних анімацій та HTML5/WebGL шаблонів.

Ключові параметри конфігурації ШІ-контуру:

* **Робочий контекст (Context Window)**: Фіксований обсяг **32 768 токенів** (із можливістю розширення до 64k+), що дозволяє утримувати в пам'яті локального агента повний математичний апарат, геодезичні матриці та інваріанти без втрати зв'язності.
* **OpenAI-Сумісний Проксі (`http://localhost:11434/v1`)**: Для усунення проблеми зависання інструментів (Tool Calling / Function Calling) у розширеннях VS Code (Cline / Roo Code), взаємодія з Ollama налаштована через OpenAI-сумісний еліас. Це забезпечує точне розпізнавання JSON-структур виклику читання та запису файлів.
* **Автономний режим (Auto-Approve)**: Увімкнення режимів автоматичного підтвердження читання файлів, внесення змін та виконання синтаксичних тестів у терміналі для досягнення безперервного інженерного циклу.

## 4. Трирівнева Шлюзова Архітектура Розподілу Праці (Multi-Agent Division of Labor)

Для виключення витоку хмарних токенів та забезпечення контекстної чистоти в системі впроваджено суворе розділення ролей за трьома ізольованими рівнями. Взаємодія між рівнями здійснюється через дискретну файлову пам'ять (Stateful Environment Protocol) та стандартизовані Markdown-директиви.

Архітектурна схема розподілу праці виглядає наступним чином:

```
[ РІВЕНЬ 1: Хмарний Стратег & Архітектор ] ──(Gemini Notebook)
             │
             ▼ 1-Click Relay (Директива у .v4_gateway/in/)
[ РІВЕНЬ 2: Файловий Шлюз ] ──────(.v4_gateway/in/ & out/)
             │
             ▼ Автономна кодогенерація & Pre-Commit Check
[ РІВЕНЬ 3: Локальний Виконавець ] ──(VS Code + Cline + Ollama qwen2.5-coder)
```

Функціональні обов'язки рівнів розподілені чітко та безперечно:

### Рівень 1: Хмарний Стратег & Архітектор (Cloud Architect)
* **Середовище**: Gemini Notebook у браузерному контурі.
* **Завдання**: Проведення системного аудиту джерел, розробка теоретичного фізико-математичного апарату, формування канонічних специфікацій та генерація атомарних `.md` директив для розгортання.

### Рівень 2: Файловий Шлюз та Стан-Пам'ять (File Gateway & State Memory)
* **Середовище**: Каталог `.v4_gateway/` у корінному репозиторії проєкту.
* **Структура**:
  * `.v4_gateway/in/` — вхідні директиви для виконання (наприклад, `cline-directive-math-engine.md`, `cline-directive-archive-and-sync.md`).
  * `.v4_gateway/out/` — вихідні паспорти системного стану та телеметрія.
  * `.v4_gateway/archive/v3_legacy/` — ізольований архів застарілих специфікацій v3.0.

### Рівень 3: Локальний Інженер-Виконавець (Local Code Executor)
* **Середовище**: ПК Користувача (VS Code + розширення Cline / Roo Code + Ollama `qwen2.5-coder`).
* **Завдання**: Зчитування директив із файлового шлюзу, генерація Python-модулів, виконання синтаксичної перевірки, запуск автономних тестів та фіксація результатів у Git-комітах.

## 5. Специфікація Локального Математичного Ядра (`core/math_engine/`)

Центральним обчислювальним компонентом проєкту Imperia v4 є модульне Математичне Ядро на Python, що розташоване у папці `core/math_engine/`. Задля швидкого та надійного розгортання ядра створено автономний скрипт розгортання `build_math_engine.py`, який будує структуру файлів без залучення сторонніх залежностей.

Структура модулів Математичного Ядра та їхній математичний вміст подано нижче:

```
imperia_v4/
└── core/
    └── math_engine/
        ├── __init__.py         # Фасадна точка входу ядра
        ├── h3_grid.py          # Мапінг M-f осі на Uber H3 геодезичні сітки
        ├── coherence_q.py      # Розрахунок Q-фактора, динаміки dQ/dt та Peff
        ├── vectors_e.py        # 4D-вектор середовища E та канонічні хаби
        ├── wave_physics.py     # 6D фізика (3L, 3T), Джиттербаг та фазовий Phase-Lock
        └── test_engine.py      # Набір модульних тестів (PyTest / Unittest)
```

### 5.1. Модуль Просторово-Часової Кластеризації (`h3_grid.py`)
Зв'язує 204.08-октавну масштабно-частотну вісь $M-f$ із геопросторовими хексагонами Uber H3 (роздільна здатність Res 0 ... 15). Кожній октаві відповідає чіткий просторовий масштаб та Варнова роль.

Розрахунок номеру октави здійснюється за логарифмічним співвідношенням:

$$N_{\text{octave}} = \lg(L) \cdot \log_2(10) \approx \lg(L) \cdot 3.321928$$

Калібрувальна матриця $M-f$ осі реалізована у вигляді структурованого мапінгу:

| Октава ($M_k$) | Масштаб ($L$) | Uber H3 Res | Опис Сутності | Варнова Роль |
| :--- | :--- | :--- | :--- | :--- |
| **$M_0$ (Sub-Edge)** | $10^{-2} \dots 10^0\text{ м}$ | Res 15 – 12 | IoT-сенсор, NPU-чип, апаратний модуль | Периферія (Шудра-Клітина) |
| **$M_1$ (Micro-Personal)** | $10^0 \dots 10^2\text{ м}$ | Res 11 – 10 | Персональний пристрій, особа | Шудра / Вайш'я |
| **$M_2$ (Meso-0: Oseredok)** | $10^2 \dots 10^3\text{ м}$ | Res 9 ($\sim 0.1\text{ км}^2$) | Локальний осередок, P2P-сусідство | Вайш'я / Кшатрій |
| **$M_3$ (Meso-1: District)**| $10^3 \dots 10^4\text{ м}$ | Res 8 – 7 ($\sim 5.2\text{ км}^2$) | Міський район, мікро-хаб | Кшатрій (Regional Router) |
| **$M_4$ (Meso-2: Regional)**| $10^4 \dots 10^5\text{ м}$ | Res 6 – 4 ($\sim 11\,000\text{ км}^2$)| Обласний Соборний Хаб (Київ, Львів) | Брахман (Swarm Orchestrator) |
| **$M_5$ (Macro: State)** | $10^5 \dots 10^6\text{ м}$ | Res 3 – 1 ($\sim 1\,000\,000\text{ км}^2$)| Суверенний державний контур | Канонічний Контур (Master UI) |
| **$M_6$ (Meta: Biosphere)** | $10^6 \dots 10^7+\text{ м}$| Res 0 ($\sim 4\,250\,000\text{ км}^2$) | Планетарна P2P-мережа Ноосфери | Глобальний Синхронізатор |

### 5.2. Модуль Когерентності та Ефективної Потужності (`coherence_q.py`)
Описує добротність інформаційного поля $Q(t)$ та розраховує фазове згасання й ресинхронізацію:

$$Q(t) = Q_0 \cdot e^{-\lambda t} + \sum \Delta Q_{\text{sync}}$$

Динаміка зміни когерентності задається диференційним рівнянням:

$$\frac{dQ}{dt} = \alpha (Q_{\text{target}} - Q) - \beta \cdot \text{Jitter} + \gamma \cdot \text{Feedback}$$

Шкала когерентності ділиться на три діагностичні зони:
* **Зелений рівень ($Q \ge 0.90$)**: Повна синархічна та фазова когерентність контуру (`#00ffcc`).
* **Жовтий рівень ($0.75 \le Q < 0.90$)**: Оперативна стабільність вузла (`#ffcc00`).
* **Червоний рівень ($Q < 0.75$)**: Фазовий розсинхрон, необхідна резонансна затяжка (`#ff3366`).

Ефективна потужність поля $P_{\text{eff}}$ розраховується як добуток норми 4D-вектора середовища та коефіцієнта когерентності:

$$P_{\text{eff}} = |\vec{E}| \cdot Q$$

### 5.3. Модуль 4D-Вектора Середовища (`vectors_e.py`)
Обчислює багатовимірний вектор середовища $\vec{E}$, складові якого нормуються в діапазоні $[0.0, 1.0]$:

$$\vec{E} = \begin{bmatrix} E_{\text{lang}} \\ E_{\text{geo}} \\ E_{\text{hist}} \\ E_{\text{soc}} \end{bmatrix}$$

де $E_{\text{lang}}$ — мовно-культурний коефіцієнт, $E_{\text{geo}}$ — просторова щільність H3, $E_{\text{hist}}$ — історико-хронологічна спадкоємність, а $E_{\text{soc}}$ — коефіцієнт синархічної довіри.

### 5.4. Модуль 6D Хвильової Фізики (`wave_physics.py`)
Базується на просторово-часовій системі $(3L, 3T)$ Бартіні-Кузнецова. За теоремою Ньотер, однорідність часу визначає збереження фундаментального інваріанта потужності:

$$[L^5 T^{-5}] = \text{Const}$$

Основні фізичні величини виводяться через довжину $L$ та час $T$:
* **Маса та Заряд**: $M = q = [L^3 T^{-2}]$
* **Сила**: $F = [L^4 T^{-4}]$
* **Енергія**: $E = [L^5 T^{-4}]$
* **Магнітний обертальний вихор**: $B = [L^2 T^0]$

Фазовий перехід Джиттербагу Фуллера між Кубоктаедром ($Q=1$, Out-Wave) та Тетраедром ($Q \ge 0.95$, In-Wave) описується неперервним зміщенням 12 вершин під кутом $\theta \in [0^\circ, 70.53^\circ]$, де $70.53^\circ = \arccos(1/3)$.

Фазове затягування частот резонаторів Гельмгольца (триплет Шумана 3.915 Гц, 7.830 Гц, 15.660 Гц) регулюється рівнянням Адлера:

$$\frac{d(\Delta \phi)}{dt} = \Delta \omega - K \cdot \sin(\Delta \phi)$$

## 6. Медіа-Стек Візуалізації та Графічного Прискорення

Для високоефективного рендерингу математичних моделей у роздільній здатності 4K (60 FPS) розгорнуто локальний медіа-пайплайн, що поєднує інструменти анімації та веб-візуалізації.

Компоненти медіа-стека включають:

* **Manim (Mathematical Animation Engine)**: Створення 3D-сцен, морфінгу Платонових тіл та векторних полів.
* **FFmpeg**: Двопрохідне склеювання кадрових буферів у формати MP4 та оптимізовані GIF-анімації.
* **Three.js & WebGL**: Інтерактивні 3D-панелі в браузері (`docs/index.html`) з підтримкою матеріалів `MeshPhysicalMaterial`, `OrbitControls` та розширень `lil-gui`.
* **Науковий стек Python**: `numpy`, `scipy`, `moviepy`, `Pillow`, `opencv-python` для накладання ефектів сяйва (bloom) та матричних обчислень.

3. **Фіксація стану в Git**: Кожен етап розгортання запечатується атомарними комітами. Зміни синхронізовано з GitHub у коміті `ccdd8c7` (*"docs(v4.0): sync master architecture spec and gateway directives"*).
