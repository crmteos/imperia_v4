# ТЕХНІЧНЕ ЗАВДАННЯ (v3.0): Архітектура Ізольованих Середовищ та Суверенного Моніторингу (Master Workbench vs Kassator Executive Workbench)

**Документ**: Архітектурне технічне завдання (Версія 3.0)  
**Цільовий репозиторій ядра**: `crmteos/imperia_v4`  
**Репозиторій адаптера інтеграції**: `crmteos/imperia-slate-adapter`  
**Файли інтерфейсу**: `imperia_v4/docs/index.html` (Master Sovereign UI) та `imperia_v4/docs/kassator.html` (Kassator Executive Workbench)  
**Модуль шлюзу**: `imperia_v4/docs/sl8_gateway.js`  
**Статус**: Офіційне архітектурне рішення щодо розмежування середовищ та суверенного нагляду  

---

## 1. Причина Рефакторингу та Перегляду ТЗ (Усунення Колізії v2.0)

Під час практичної імплементації версії 2.0 виникла колізійна архітектурна помилка: завдання із гуманізації глобального інтерфейсу Imperia v4 та специфічні метрики кабінету Дмитра (Kassator) розроблялися всередині одного й того ж файлу `index.html`. Це призвело до змішування контекстів, порушення ізоляції даних та збою робочої сесії.

**Рішення версії 3.0**:
Повна фізична та логічна декомпозиція інтерфейсного шару на два незалежні середовища з чітким розмежуванням прав доступу, стану та функціонала.

---

## 2. Подвійна Модель Розуміння Системи

### 2.1. Антропоморфна Модель (Для Власника Проєкту)
Метафора **«Головного Командного Центру Мережі та Автономного Дослідницького Шатлу»**:

* **`index.html` (Головний Командний Центр)**:
  Це ваша особиста флагманська станція. Ви бачите всю галактику Imperia v4: стан 5 P2P-хабів (Київ, Львів, Одеса, Харків, Дніпро), глобальну когерентність $Q=0.94$, навантаження Swarm Inference та радар усіх підключених модулів.
* **`kassator.html` (Персональний Кабінет / Шатл Дмитра)**:
  Це окремий, стильний та ізольований кокпіт Дмитра. Він не бачить ваших системних важелів, коду чи внутрішньої кухні ядра. У своєму кабінеті він бачить інструменти для свого продукту: аналітику Sl8, розгадку «Японського феномену», помічника Brahman AI та симулятор токена SSLX.
* **Лінія Суверенного Моніторингу (Телеметрія)**:
  Шатл Дмитра передає діагностичні сигнали на ваш Головний Командний Центр. Ви бачите на своєму радарі в `index.html`, як працює його середовище, але його дії не перетинаються з кодом вашої центральної станції.

### 2.2. ШІ-Архітектурна Модель (Для Головного Архітектора)

```
┌──────────────────────────────────────────────────────────────────────────┐
│                      Imperia v4 Sovereign Core                           │
│                      (crmteos/imperia_v4)                                │
│  - Global State Manager ($Q = 0.94$, P2P Topology 101-105)               │
│  - Swarm Inference Engine & Memory Scoping                               │
└──────────────────▲────────────────────────────────────▲──────────────────┘
                   │                                    │
    [ Master RPC / Admin Channel ]        [ Tenant RPC / Scoped Channel ]
                   │                                    │
┌──────────────────┴──────────────────┐  ┌──────────────┴──────────────────┐
│  index.html (Master Sovereign UI)   │  │ kassator.html (Executive UI)     │
│  - Full System Control & Governance │  │ - Dedicated Tenant View          │
│  - Kassator Telemetry Monitor Widget│  │ - Kassator Brahman AI Copilot    │
│  - Human-Centric UI & $Q$-Control   │  │ - Sl8 Analytics & SSLX Simulator │
└──────────────────▲──────────────────┘  └──────────────▲──────────────────┘
                   │                                    │
                   └───────────[ sl8_gateway.js ]───────┘
                     Multi-Tenant Event Bus & Telemetry
```

1. **Фізична файлова ізоляція**:
   - `index.html`: Суверенний панельний шар розробника/архітектора (Master Control & Global Telemetry).
   - `kassator.html`: Клієнтський шар Дмитра (Tenant Executive UI).

2. **Мульти-тенантний Event Bus (`sl8_gateway.js`)**:
   - Екземпляр `SL8Gateway` ініціалізується з контекстом `tenantId`.
   - Для `kassator.html` генерується ізольований сесійний токен `tenantId: "kassator"`.
   - Усі події та стани клієнтського кабінету ізолюються у просторі імен `state.tenants["kassator"]`.

3. **Телеметрія та Master Override (Суверенний Контроль)**:
   - `sl8_gateway.js` транслює у фоновому режимі події `TELEMETRY_STREAM` з `kassator.html` до `index.html`.
   - `index.html` містить віджет **"Kassator Node Monitor"**, який дозволяє Власнику бачити статус вузла Дмитра, рівень запитів, обчислювальне навантаження та показники $E_{soc}$.
   - При потребі `index.html` має адміністративні функції перевизначення (Master Override): `pauseTenant()`, `recalibrateQBounds()`, `setInferenceCap()`.

## 3. Деталізація Функціонала по Файлах

### 3.1. `imperia_v4/docs/index.html` (Master Sovereign UI)
- **Призначення**: Повний контроль над проєктом Imperia v4.
- **Компоненти**:
  1. Глобальна карта P2P-мережі (вузли 101–105).
  2. Панель управління глобальною когерентністю ($Q$).
  3. Віджет моніторингу зовнішніх клієнтських середовищ (зокрема віджет `Kassator Node Status`).
  4. Інтерфейс управління Swarm Inference та конфігураціями.

### 3.2. `imperia_v4/docs/kassator.html` (Kassator Executive Workbench)
- **Призначення**: Персональний робочий простір Дмитра (засновника Sl8).
- **Компоненти**:
  1. Інтерактивний чат із персональним **Brahman AI-консультантом**.
  2. Панель аналітики Sl8 (діагностика $E_{soc}$, кейс «Японія», кластеризація користувачів).
  3. Симулятор PoC-токеноміки (моделювання виплат у токенах SSLX на базі Stellar).
  4. Карта залученості H3 Grid без доступу до адміністративних важелів Imperia v4.

### 3.3. `imperia_v4/docs/sl8_gateway.js` (Multi-Tenant Engine)
- **Розширення класу `SL8Gateway`**:
  - `initTenantSession(tenantId, apiToken)` — ініціалізація ізольованого сеансу.
  - `emitTelemetry(tenantId, payload)` — передача діагностичних даних на Master UI.
  - `executeMasterCommand(command, tenantId)` — виконання адміністративних вказівок з `index.html`.
