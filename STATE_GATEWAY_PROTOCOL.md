## 4. ⚖️ Принцип Автоматичної Інженерної Трансляції (Zero-Budget Standard Rule)

1. **Приоритет Мови Користувача**:
   Користувач формулює завдання, поняття та візію у своїй природній термінології (контексти Imperia v4, хвильова геометрія, Варновий консенсус тощо).

2. **Заборона штучного ускладнення (Бюджет = 0)**:
   При бюджеті = 0 заборонено проектувати кастомні велосипедні конструкції, саморобні формати даних чи екзотичні схеми.

3. **Автоматична трансляція на стандарти IT/GIS**:
   ШІ-Архітектор та Клін зобов'язані **автоматично перекладати** понятійний апарат Користувача на готові класичні open-source стандарти (ETL, H3 Spatial Grid, Leaflet Choropleth, Kademlia DHT, Vector Indexes, SQL/NoSQL) і пропонувати їх на випередження.

4. **Інваріант Не-self-Реалізації**:
   Якщо готовий open-source стандарт може вирішення проблеми користувача — зобов'язаність інженера — використати готовий стандарт, а не створювати новий.
   *Цей інваріант гарантує, що ресурси direccionуються до інтеграції та адаптації, а не до ізоляції «власних розробок».*

5. **Пропозиція Стандартного Рішення**:
   Клін зобов'язаний сформулювати пропозицію у вигляді:
   - "Ви можете використати готовий стандарт X для вашого випадку Y"
   - з посиланням на документацію та доказ здатності標準 вирішити problemas користувача
   - без створення додаткових артефактів при бюджеті = 0.

## 5. Протокол Атомарного Виконання Директив (Cline Execution Constraints)
- Директива Брахмана містить ізольовані кроки (переважно 1 файл / 1 дія).
- Клін зобов'язаний повністю завершити поточний крок, перевірити його працездатність і зробити коміт перед виконанням наступного.

### 5.2. Правило Жорсткого Перезапису (Hard Overwrite Rule)
- При оновленні монолітних скриптів та HTML-шаблонів Клін виконує **повне перезаписування файлу** (або видалення старого файлу та створення нового).
- Суворо заборонено частково дописувати нові блоки у старий файл, якщо це призводить до дублювання блоків `<script>` чи маніпуляцій з DOM.

### 5.3. Pre-Commit Syntax Validation
- Клін зобов'язаний виконати перевірку синтаксису коду перед `git commit`.
- Позначка `[x]` у `master_checklist.md` є підтвердженням того, що код успішно пройшов синтаксичний контроль.
